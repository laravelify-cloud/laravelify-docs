A **group** is a folder for related websites, like `production`, `staging`, or one per client. Open **Groups**, create one, then add websites inside it.

## Create a website

**Groups → your group → New website**:

| Field | Notes |
| --- | --- |
| Type | Backend, Frontend, or Full-stack: Laravel, PHP, Express, NestJS, Node.js, React, Vue.js, Angular, Svelte, Astro, Static HTML, Next.js, Nuxt, or SvelteKit. Chosen once, when the site is created. See [Frameworks](/websites/frameworks) |
| Name | Shown in the panel |
| Domain | Like `example.com`. nginx uses it as `server_name`. Tick **Also open on www.example.com** to answer on both |
| Other domains | Optional, one per line. They all open this same website, so one app needs no second website. See [Several domains](#several-domains) |
| Source | A connected GitHub App, a token, or a public repository URL |
| Branch | Pushes to this branch deploy (default `main`) |
| Cloudflare tunnel | Optional. Adds the domain to that tunnel |
| PHP / Node version | PHP 8.0–8.5 for PHP sites, Node 20/22/24 for Node servers and front-end builds |
| Build settings | Optional install, build, and start commands, and the output folder |
| Create a MySQL database | PHP sites: creates a database and user and fills `DB_*` in `.env` |

The site is created under `/var/www/{slug}` with an nginx file, a process file where the type has one, and an environment file from templates. Nothing runs until the first deploy.

## The website page

| Tab | What it does |
| --- | --- |
| General | Name, domain, source, branch, tunnel, database |
| Environment | The `.env` file. Saving writes it and clears Laravel's cached config |
| Runtime | PHP or Node version, port, build and start commands, output folder, Reverb; **Regenerate files** from the templates |
| Nginx | The site's nginx file. Saving runs `nginx -t` before reloading |
| Security | Search engine blocking, crawler blocking, basic auth, blocked IPs |
| Monitoring | Live requests, charts, issues, heartbeats, attacks |
| Deployments | Deploy log, history, webhook, auto deploy |
| Logs / Health | Every log file of the site; health checks |
| Processes | Supervisor programs (Laravel) or the PM2 file (Node servers). Not shown for PHP and static sites |
| Terminal / Files | A terminal and a file manager inside the site's folder |
| Danger zone | Delete the site and everything Laravelify installed for it |

## Several domains

A website has one main domain and any number of **other domains** (a `www` name, a second domain). Add them when you create the site, or on its **General** tab (**Other domains**, with a one-click **Add www** button). nginx's `server_name` lists all of them, and a site on a Cloudflare tunnel gets a tunnel route for each. With a Cloudflare API token ([Settings → Cloudflare](/websites/cloudflare-tunnels)) Laravelify also adds each domain's DNS record. A domain can belong to only one website.

## Redirects

The **Redirects** tab (under Settings) sends visitors somewhere else, in two kinds:

- **Domain redirect.** `apply.coupons` and `www.apply.coupons` can open another site, for example `https://supercell.apply.coupons`. Leave the destination blank to send the domain to this website's own address. The path and query are kept by default (`apply.coupons/a?b=1` becomes `supercell.apply.coupons/a?b=1`), and you choose 301 or 302 (or 307 / 308 when the request method must stay). On a Cloudflare tunnel the redirecting domain is added to the tunnel and DNS like the website's other domains.
- **Page redirect.** `/old-page` goes to `/new-page` or to a full URL. Choose **This folder and everything under it** to redirect a whole path like `/blog/`.

Saving rewrites nginx (domain redirects as their own `server` blocks at the end of the file, page redirects inside the website's first `server` block, both marked as managed by the panel) and reloads it. nginx checks the file first; a rejected file is put back and nothing changes. A domain that is one of this website's own domains, or belongs to another website, cannot be used as a redirect. Your MCP assistant does the same with `set-redirects`.

## Turn off and on

A website or a whole group can be turned off without deleting anything:

- The address shows a short **This site is turned off** page (HTTP 503) on the same domain and port.
- Queue workers and the Node process stop, and they do not come back after a reboot.
- Deploys, pushes from GitHub, and down alerts pause.
- Files, the database, the environment, and every setting stay. **Turn on** writes the site's files again and brings back exactly what was there.

Turn one website off in its **Danger zone**, or a whole group with **Turn off group** on the group page. A turned-off group turns off every website in it.

Turning a group or several websites on or off runs in the queue, like backups. A progress card shows which website it is on and lists each one with its result (turned off, already off, or the error). Rows still waiting show **Switching…**. A website that fails keeps its state, so you can fix it and try again.

## Select several

The **Groups** list and a group's websites have a checkbox on every row and one to select all. With rows selected, a bar shows **Turn on**, **Turn off**, and **Delete**:

- Deleting websites removes their nginx, worker, and PM2 files and the websites in the panel. Their folders in `/var/www` are kept.
- Only empty groups are deleted. Groups that still have websites are kept, and the panel tells you which.
- Both ask you to type `delete` first (a copy button pastes it).

## Ports

Node servers (Express, NestJS, Next.js, Nuxt, SvelteKit, Node.js) get ports from 3000 upward, Reverb from 8080 upward, and sites without a domain an HTTP port from 8081 upward. Laravelify picks a port nothing uses: not another website, not a service, and not any process listening on the server right now. You can change it on the Runtime tab; **Server → Reserved ports** shows what holds which port.

<Note>
  Changing the PHP or Node version, the port, or Reverb does not overwrite a hand-edited nginx file. Use **Regenerate files** when you want the template again.
</Note>
