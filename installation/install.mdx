## Install

SSH into the server as a user that can use `sudo`, then run:

<InstallCommand />

The installer first asks where the panel lives:

- **A free `https://<name>.laravelify.cloud` address**: paste the install key from [app.laravelify.cloud](https://app.laravelify.cloud) → Dashboard → **Install from a terminal**. Laravelify Cloud makes the tunnel and its DNS record, so nothing else about Cloudflare is asked. The server keeps an id in `/etc/laravelify/cloud-server-id`, so installing it again gives the same address. Each account has a few free addresses; deleting a server in Laravelify Cloud frees its address.
- **Your own domain**, on your own Cloudflare tunnel. Then it asks for:

| Prompt | Example | Used for |
| --- | --- | --- |
| Cloudflare tunnel token | `eyJh…` | Connects the server to Cloudflare. Asked first and checked; the whole `cloudflared service install …` command works too |
| Cloudflare API token (optional) | `Gq3…` | Adds the panel's route on the tunnel and its DNS record, and is saved in **Settings → Cloudflare**. A tunnel token cannot do this. Create one under My Profile → API Tokens with Account → Cloudflare Tunnel → Edit and Zone → DNS → Edit. Press Enter to skip and add the route by hand. |
| Laravelify panel domain | `panel.example.com` | The panel's address |

The database password is not asked: the installer makes a random 40-character one for MySQL or MariaDB root (and phpMyAdmin sign-in), PostgreSQL's `postgres`, and MongoDB's `admin`. The panel shows it on **Server → MySQL** after your authenticator code, and you can change it there. To pick your own, run the installer with `MYSQL_ROOT_PASSWORD=...`.

phpMyAdmin is not asked either: it opens at `https://<panel domain>/phpmyadmin`. Change the path later on **Server → phpMyAdmin**.

It always installs the **latest release**: the command downloads the installer of the newest GitHub release, and that installer downloads the matching panel.

### What you see

The installer works through the install one step at a time. Each step shows a spinner while it runs and a check mark with its time when it is done, so you always know where it is. What the commands print goes to `/var/log/laravelify-install.log` (readable only by root). When a step fails, it stops there and shows the last lines of that log.


## Choose what to install

By default the installer adds PHP-FPM 8.4, Node.js 24, and MySQL, so it finishes in a few minutes. Any other version is installed by the panel the first time a website needs it (one to three minutes). To install more up front, use the **install command builder** on [laravelify.cloud](https://laravelify.cloud/#install). Pick what you will run (Laravel 12, Next.js 16, …) and only the versions those need are ticked; pick the databases; optionally type your domains, and copy the command. Or write the options yourself:

```bash
curl -fsSL https://cdn.laravelify.cloud/install.sh | sudo bash -s -- --php=8.4 --node=22 --databases=mysql,postgresql
```

| Option | Example | Description |
| --- | --- | --- |
| `--php=LIST` | `--php=8.2,8.4` | PHP-FPM versions: 7.4, or 8.0 to 8.5. Websites can pick any other one later: the panel installs it when a site needs it. The panel itself needs 8.3 or newer, so 8.4 is added when none of 8.3, 8.4, 8.5 is chosen. |
| `--node=LIST` | `--node=22,24` | Node.js majors: 18, 20, 22, 24. Any other release (like 19.0.0) can be set per website and is downloaded on its first deploy. The newest one is the system Node.js (npm, PM2, and sites set to a version that is not installed). |
| `--databases=LIST` | `--databases=mariadb,postgresql` | Database servers for your websites: `mysql` or `mariadb` (one of the two), `postgresql`, `mongodb`, or `none`. Default: `mysql`. SQLite always works: it is a file, not a server. Without MySQL or MariaDB the panel keeps its own data in SQLite and phpMyAdmin is left out. |
| `--panel-domain=HOST` | `--panel-domain=panel.example.com` | The panel's domain (otherwise asked) |
| `--tools=LIST` | `--tools=phpmyadmin,vscode` | Optional tools: `phpmyadmin`, `vscode` (VS Code in the browser), `glitchtip` (error tracking, set up after the first sign-in), or `none`. Default: `phpmyadmin,vscode` (phpMyAdmin only with MySQL or MariaDB). |
| `--phpmyadmin-path=PATH` | `--phpmyadmin-path=/db` | phpMyAdmin's path on the panel's address, with `--tools=phpmyadmin`. Default: `/phpmyadmin`. |
| `--help` | | Prints the options |

The Cloudflare tunnel token has no option on purpose: it is always asked on the server (or given as an environment variable, below), so they never end up in a copied command or your shell history.

To add a version later, run a repair with the new list, like `curl -fsSL https://cdn.laravelify.cloud/install.sh | sudo LARAVELIFY_REINSTALL=1 bash -s -- --php=8.2,8.3,8.4`. It installs only what is missing.

When it finishes it prints the setup link, like `https://panel.example.com/setup?token=...`. Open it to create the admin account and turn on two-factor authentication. Without the token `/setup` does not open, so nobody who finds a fresh panel first can claim it (the token is also in `/opt/laravelify/.env` as `LARAVELIFY_SETUP_TOKEN`).

## Running it again

If Laravelify is already installed, running the install command again only updates it. It shows the installed and new version and asks `Update Laravelify only? [Y/n]`. Packages such as PHP, MySQL, Node, and pm2 are not checked or reinstalled. Answer `n`, or run with `LARAVELIFY_REINSTALL=1`, to repair the whole install.

A repair run skips what is already installed, and nothing needs retyping: it shows the answers from last time and asks whether to use them.

```text
Found the settings from a previous install:
  Panel domain:            panel.example.com
  Database password:       ******** (saved)
  Cloudflare tunnel token: ******** (saved)
Use these settings? [Y/n]
```

Press <kbd>Enter</kbd> to reuse them, or type `n` to answer every question again. The answers are kept in `/etc/laravelify/install.env`, readable only by root; the uninstaller removes it.

## Unattended install

Every prompt can be given as an environment variable, which is handy for provisioning scripts:

```bash
curl -fsSL https://cdn.laravelify.cloud/install.sh | sudo \
  PANEL_DOMAIN=panel.example.com \
  CLOUDFLARE_TUNNEL_TOKEN='eyJh…' \
  bash
```

| Variable | Default | Description |
| --- | --- | --- |
| `MYSQL_ROOT_PASSWORD` | 40 random characters | The database password (no spaces, quotes, or backslashes) |
| `PANEL_DOMAIN` | asked | Panel hostname |
| `PHPMYADMIN_PATH` | `/phpmyadmin` | phpMyAdmin's path on the panel's address |
| `LARAVELIFY_CLOUD_KEY` | — | An install key from app.laravelify.cloud: a free `<name>.laravelify.cloud` address, no Cloudflare questions |
| `CLOUDFLARE_TUNNEL_TOKEN` | asked | Tunnel token |
| `CLOUDFLARE_API_TOKEN` | asked (optional) | A Cloudflare API token (Account → Cloudflare Tunnel → Edit, Zone → DNS → Edit). The installer uses it to add the panel's route and DNS record, and saves it in **Settings → Cloudflare**. Set it empty to skip. |
| `LARAVELIFY_PHP_VERSIONS` | `8.4` | Same as `--php` |
| `LARAVELIFY_NODE_VERSIONS` | `24` | Same as `--node` |
| `LARAVELIFY_DATABASES` | `mysql` | Same as `--databases` |
| `LARAVELIFY_TOOLS` | `phpmyadmin,vscode` | Same as `--tools` |
| `LARAVELIFY_VERSION` | `latest` | Release to install, like `1.2.0` |
| `LARAVELIFY_REPO` | the official repository | GitHub `owner/name` to download releases from (for forks) |
| `LARAVELIFY_SOURCE` | — | Install from a local folder instead (development). Its `.env`, `storage`, and caches are never copied, so the server keeps its own keys. |
| `LARAVELIFY_ARCHIVE_URL` | — | Install from any `.tar.gz` URL instead |

## What gets installed

<AccordionGroup>
  <Accordion title="Web and PHP">
    - **nginx**, the web server for every site and the panel.
    - **PHP-FPM 8.4**, or the ones you chose with `--php` (whichever the PHP repository still publishes for your Ubuntu), with the common extensions Laravel needs (including GD, for resizing JPEG, PNG, and WebP images). Updating the panel adds GD to a PHP version that does not have it yet.
    - **Composer**.
  </Accordion>
  <Accordion title="Data">
    - **MySQL 8.4 LTS** (Ubuntu's MySQL as a fallback) by default, or **MariaDB** with `--databases=mariadb`, with a random 40-character password. **phpMyAdmin** at `/phpmyadmin` of the panel, with one-click sign-in from the panel, when you pick it with `--tools=phpmyadmin`.
    - **PostgreSQL** (`--databases=postgresql`): Ubuntu's version, on 127.0.0.1, with the same password for the `postgres` user.
    - **MongoDB 8.0** (`--databases=mongodb`): from MongoDB's repository, on 127.0.0.1, with sign-in turned on and an `admin` user with the same password.
    - **SQLite**, always: a website can keep its data in a file in its folder.
    - **Redis**, available to your sites. The panel keeps its own sessions, queue, and cache in its database: MySQL or MariaDB when installed, otherwise SQLite.
    - PHP gets the matching drivers: `pgsql` with PostgreSQL, `mongodb` with MongoDB.
  </Accordion>
  <Accordion title="Node and processes">
    - **Node.js 24**, or the ones you chose with `--node` (through `n`), and **PM2** for Node.js, Next.js, Nuxt, Python, Go, and Bun sites.
    - **Python, Go, Bun, and Hugo** are not installed up front: the first website that needs one downloads it into `/opt/laravelify-tools` (see [Frameworks](/websites/frameworks)).
    - **Supervisor**, which runs the panel's `laravelify-queue` (deploys) and `laravelify-scheduler` (monitoring, alerts), plus each Laravel site's workers.
  </Accordion>
  <Accordion title="Network and security">
    - **cloudflared**, connected with your tunnel token.
    - **ufw** firewall: deny incoming by default, allow SSH (22), 80, and 443.
    - The panel's own user, `laravelify`, with its own PHP-FPM pool. Each website runs as `lfy-<slug>` and cannot read the panel or other websites ([Users and permissions](/security/privilege-separation)).
    - A sudoers rule that lets the panel run only `scripts/host-apply.sh` as root. That script validates every argument and every file before it touches the system.
  </Accordion>
</AccordionGroup>

The panel lives in `/opt/laravelify`. Sites live in `/var/www/{slug}`.

## After installing

<Steps>
  <Step title="Add the public hostnames in Cloudflare">
    Skip this if you gave the installer a Cloudflare API token: it added them. Otherwise, tunnel → **Routes** → **Add route** → **Published application**: `panel.example.com` → `http://localhost:80`.
  </Step>
  <Step title="Create the admin and enable 2FA">
    Open the setup link the installer printed (`https://panel.example.com/setup?token=...`).
  </Step>
  <Step title="Set a Redis password">
    Redis starts without a password. Set one under **Server → Redis**.
  </Step>
</Steps>
