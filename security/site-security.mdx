Each website's **Security** tab writes nginx rules for that site only. Saving reloads nginx; workers keep running.

## Hide from search engines

Sends `X-Robots-Tag: noindex, nofollow` on every response and serves a `robots.txt` that disallows everything (unless your nginx file already serves one). Use it for staging sites, admin panels, and APIs.

## Refuse known crawlers

Answers `403` to search engine, SEO, and AI crawlers: Googlebot, Bingbot, Yandex, Baidu, Ahrefs, Semrush, GPTBot, ClaudeBot, CCBot, Bytespider, and more. Link previews in Telegram, WhatsApp, Slack, and Facebook keep working.

## Basic auth

Website → **Security** → **Basic auth** → **Require a password** asks visitors to sign in before they can open the site. Choose how:

| Way | What visitors type | Good for |
| --- | --- | --- |
| **Username and password** | A username and password you set | Sharing a staging site with a client or a team |
| **Authenticator code (2FA)** | The 6-digit code from your authenticator app, in the username **or** the password field | Sites only you open: no password to share or leak |

With the **authenticator code**, a correct code lets that browser in for **24 hours**, from the same IP address, for that website only. The browser asks again after a day, or after it is closed completely. Wrong codes count like the panel's own prompt: after 5 wrong tries the IP waits 15 minutes. It is the same code as for the panel (your admin's authenticator), and nginx asks the panel to check it before every page.

Add paths that stay open (one per line, prefix match), for example APIs and webhooks that servers call without a browser. They work in both ways:

```text
/api/
/hooks/
/socket.io/
```

`/.well-known/acme-challenge/` is always open. A password is stored as a SHA-512 crypt hash for nginx, plus encrypted so you can reveal it later with your 2FA code. The authenticator code way stores nothing per site.

## Blocked IPs

IPs and CIDR ranges (IPv4 or IPv6), one per line, answered with `403`:

```text
203.0.113.7
198.51.100.0/24
2001:db8::/32
```

Blocking uses the visitor's real IP, also behind a Cloudflare tunnel (`CF-Connecting-IP` is trusted only from the local tunnel). You can block an attacker in one click from **Monitoring → Security**.

<Tip>
  For blocking at Cloudflare's edge (before traffic reaches your server), add the IP to a WAF rule in the Cloudflare dashboard.
</Tip>
