<AccordionGroup>
  <Accordion title="Migrations fail: 1419 You do not have the SUPER privilege and binary logging is enabled">
    MySQL 8 keeps a binary log, and then only SUPER may create triggers, functions, and procedures. Update to 0.3.0-beta.19 or later: the update turns on `log_bin_trust_function_creators` (with `SET PERSIST`, so no restart), and new servers have it from the start. Then deploy the site again.

    By hand, on the server (MySQL's root has a password on Laravelify servers, so plain `sudo mysql` is refused; this uses the panel's saved login):

    ```bash
    cd /opt/laravelify && sudo -u laravelify php artisan laravelify:mysql-defaults
    ```
  </Accordion>

  <Accordion title="phpMyAdmin does not import a .sql file (No data was received / file too large)">
    Ubuntu's PHP accepts only 2 MB uploads. Update to 0.3.0-beta.20 or later: phpMyAdmin and the panel then accept 256 MB and run up to 10 minutes. The Import page shows the limit under the file picker.

    Before importing a full dump into a site's database, drop the tables the site's migrations already made, or the import stops at "Table already exists". Dumps with triggers need the setting from the entry above.
  </Accordion>

  <Accordion title="First deploy of a Laravel site with a database: Access denied for user">
    Before 0.3.0-beta.18 the migrations ran before the panel created the database and its user. Update and deploy again; the database is now made first.
  </Accordion>
  <Accordion title="The panel shows 404 or 'Permission denied' after an update">
    Version 0.2.0-beta.2 reset `/opt/laravelify` to a mode nginx cannot read. Fix it once, then update again:

    ```bash
    sudo chmod 755 /opt/laravelify
    ```

    Releases from 0.2.0-beta.3 keep the permissions.
  </Accordion>

  <Accordion title="A Nuxt or SvelteKit site fails with 'module is not defined in ES module scope'">
    The PM2 file was named `ecosystem.config.js`, which breaks in projects with `"type": "module"`. Update to 0.2.0-beta.5 or later: the file is now `ecosystem.config.cjs`, and old files are renamed on the next update.
  </Accordion>

  <Accordion title="Next.js: next build did not create .next/standalone/server.js">
    Add `output: "standalone"` to your `next.config` and deploy again.
  </Accordion>

  <Accordion title="SvelteKit: Could not detect a supported production environment">
    Install `@sveltejs/adapter-node` and use it in your SvelteKit config instead of `adapter-auto`.
  </Accordion>

  <Accordion title="The installer stops at 'repo.packagist.org could not be fully loaded'">
    A warning, not an error: Composer could not reach Packagist and used its cache. If the install stops there, the server usually cannot reach IPv6 addresses. Prefer IPv4 and run the installer again:

    ```bash
    sudo bash -c 'grep -q "^precedence ::ffff:0:0/96" /etc/gai.conf || echo "precedence ::ffff:0:0/96  100" >> /etc/gai.conf'
    ```
  </Accordion>

  <Accordion title="The panel or a site shows a Cloudflare 502 or 1033 error">
    The tunnel is not connected or the public hostname is missing.

    ```bash
    sudo systemctl status cloudflared 'laravelify-tunnel-*'
    ```

    In Cloudflare, check the tunnel is **Healthy** and the hostname points to `http://localhost:80`.
  </Accordion>

  <Accordion title="A deploy fails at git fetch with 'Authentication failed'">
    The GitHub App is not installed on that repository, or the personal token expired or lacks **Contents: read**. Open **Sources**, check the repository is listed, then deploy again.
  </Accordion>

  <Accordion title="A deploy stays 'queued'">
    The queue worker is not running:

    ```bash
    sudo supervisorctl status laravelify-queue
    sudo supervisorctl restart laravelify-queue
    ```
  </Accordion>

  <Accordion title="Monitoring shows no requests">
    Click **Turn on tracking** on the website's Monitoring tab, then visit the site. If it still shows nothing, check the scheduler runs (`sudo supervisorctl status laravelify-scheduler`) and that `/var/log/laravelify/{slug}.metrics.log` grows when you visit the site.
  </Accordion>

  <Accordion title="Next.js: 'Script not found: .next/standalone/server.js'">
    Add `output: 'standalone'` to `next.config` and deploy again. Before the first successful build there is nothing for PM2 to start; that is expected.
  </Accordion>

  <Accordion title="Next.js sites are down after the server restarts">
    PM2 restores apps on boot through the `pm2-root` service. Set it up (and move any apps started by older versions into root's PM2) with:

    ```bash
    sudo bash /opt/laravelify/scripts/host-apply.sh pm2-boot all
    ```

    `systemctl status pm2-root` should then show it enabled. Updating the panel runs this for you.
  </Accordion>

  <Accordion title="Laravel uses old .env values">
    A cached config ignores `.env`. Saving the Environment tab clears it; from the terminal run `php artisan config:clear`.
  </Accordion>

  <Accordion title="I lost my authenticator">
    See [Reset two-factor from the server](/security/authentication#reset-two-factor-from-the-server).
  </Accordion>
</AccordionGroup>

## Where to look

| Log | Path |
| --- | --- |
| Panel | `/opt/laravelify/storage/logs/laravel.log` |
| Deploy queue | `/opt/laravelify/storage/logs/panel-queue.log` |
| Scheduler | `/opt/laravelify/storage/logs/panel-scheduler.log` |
| A site's nginx | `/var/log/nginx/laravelify-{slug}.error.log` |

Still stuck? [Open an issue](https://github.com/laravelify-cloud/laravelify/issues) with the error message and these logs (remove secrets first).
