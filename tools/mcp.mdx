---
title: "MCP: deploy with an AI assistant"
description: "Connect Claude Code, Claude Desktop, or Cursor to your panel and let it deploy and manage your websites."
---

Laravelify has a built-in [MCP](https://modelcontextprotocol.io) server. Connect an AI assistant to it and ask in plain words: *"Deploy acme/shop on shop.example.com with a MySQL database."* It picks the right site type, creates the website, deploys it, follows the log, and fixes what fails.

## 1. Create a token

In the panel open **Settings → MCP**, give the token a name (one per computer or app), and press **Create token**. It asks for your authenticator code, then shows the token **once**. Copy it.

Anyone with the token can manage this panel's websites, so keep it like a password. **Revoke** a token there at any time; the list shows when and from where each one was last used.

## 2. Connect your AI app

The server address is `https://your-panel-domain/mcp`. The **Settings → MCP** page shows these commands with your address and token filled in.

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http laravelify https://panel.example.com/mcp --header "Authorization: Bearer YOUR_TOKEN"
    ```
  </Tab>
  <Tab title="Claude Desktop">
    **Settings → Developer → Edit config**, add this to `claude_desktop_config.json`, and restart Claude Desktop (needs Node.js):

    ```json
    {
      "mcpServers": {
        "laravelify": {
          "command": "npx",
          "args": ["-y", "mcp-remote", "https://panel.example.com/mcp", "--header", "Authorization:${AUTH}"],
          "env": { "AUTH": "Bearer YOUR_TOKEN" }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Cursor and others">
    `.cursor/mcp.json` (other apps that take a remote server with headers use the same shape):

    ```json
    {
      "mcpServers": {
        "laravelify": {
          "url": "https://panel.example.com/mcp",
          "headers": { "Authorization": "Bearer YOUR_TOKEN" }
        }
      }
    }
    ```
  </Tab>
</Tabs>

## 3. Ask it

- "Deploy **acme/shop** on **shop.example.com** with a MySQL database."
- "Deploy this project folder to my Laravelify server on **app.example.com**."
- "Why did the last deploy of **shop** fail? Fix it and deploy again."
- "Set **MAIL_HOST** and **MAIL_PORT** on **shop**."
- "Which of my websites are turned off?"
- "Upload the Firebase key from my backup's private.tgz into storage/app/private of the API site."

Claude also offers a ready-made **deploy-project** prompt: give it a repository or a folder and a domain.

## What it can do

| Tool | What it does |
| --- | --- |
| **Deploy** | |
| `create-website` | Create a site from a repository (or an example project) on a domain or HTTP port, with `www` and other domains, env variables and a MySQL database, and deploy it |
| `deploy-website`, `cancel-deployment` | Deploy again, or stop a deploy that hangs |
| `get-deployment`, `list-deployments` | Follow a deploy's status and log, and see the history |
| **Look** | |
| `list-websites`, `get-website` | What runs on the server, with domains and the last deployment |
| `list-groups`, `list-site-types`, `list-sources`, `list-ports` | Groups, the kinds of app, the GitHub Apps (and their repositories), tunnels, and which port is used by what |
| `server-status` | CPU, memory, disk, uptime, and the state of nginx, MySQL, Redis, Supervisor, PHP-FPM, and the tunnel |
| **Change** | |
| `update-website` | Name, repository, branch, auto deploy, GitHub App, PHP and Node version, install/build/start commands, output folder |
| `set-domains`, `sync-cloudflare` | One main domain plus any number of extra ones (`www`, a second domain) for the same site, in nginx, the tunnel, and Cloudflare DNS |
| `get-environment`, `update-environment` | Read (secrets hidden unless you ask) and set or remove `.env` variables |
| `get-nginx`, `update-nginx` | Read and change a site's nginx block, for example to send OAuth or payment callback paths to a Laravel API. nginx checks it first; a rejected file is put back |
| `set-website-enabled`, `restart-website` | Turn a site off or on; restart its PM2 app or Supervisor workers |
| **Debug** | |
| `get-logs`, `check-website` | The Laravel, worker, PM2, and nginx logs; a health check of the site, its workers, nginx, and the last deploy |
| `run-command` | One command in the site's folder as the web user, like `php artisan migrate --force` (the same as the panel's Terminal) |
| **Files and data** | |
| `list-files`, `read-file` | Browse a site's folder and read text files (`.env` only through `get-environment`) |
| `upload-file` | Put a file the repository does not carry into the site (like a Firebase key in `storage/app/private`), or unpack a `.zip`, `.tar.gz`, or `.tgz` into a folder. Up to 20 MB |
| `delete-file` | Move a file or folder to the panel's Trash, where it can be restored |
| `import-database`, `get-task` | Import a `.sql` or `.sql.gz` dump from the site's folder into its database as the site's own database user, in the background |
| **Backups** | |
| `list-backups`, `run-backup` | See the S3 backups and start one (or a full backup) now |
| **Clean up** | |
| `delete-website`, `update-group`, `delete-group`, `create-group` | Delete a site (its folder and database stay), rename or delete groups. Deleting asks for the site's slug as confirmation |

## Deploying a folder from your computer

The server cannot read files on your computer, so the assistant pushes the folder to a new private GitHub repository first (`gh repo create --private --source . --push`), then deploys that repository. Make sure your Laravelify GitHub App can read it (GitHub → **Settings → Applications** → the App → **Repository access**). After that, every push deploys by itself.

## Domains: one site, many names

A website has one main domain and any number of extra domains that open the same site, so you never need a second website for `www.example.com` or for a second domain. Ask for it in words ("deploy this on x.com and www.x.com, and y.com too") and the assistant uses `include_www` and `aliases`, or `set-domains` later. nginx answers on all of them, and on a Cloudflare tunnel they are added to the tunnel and DNS when you saved a Cloudflare API token in **Settings → Cloudflare** (see [Cloudflare tunnels](/websites/cloudflare-tunnels)).

## Private files and ports

- **Private files.** Keys and certificates are not in Git. After a site's first deploy, the assistant uploads them with `upload-file` (a single file or an archive it unpacks). Deploys keep them: a deploy only resets files that Git tracks. Paths must stay inside the site folder, and links inside archives are skipped.
- **Ports are picked for you.** Every new site gets a port that nothing uses: not another website, not a Laravelify service, and not anything listening on the server right now (for example an app still running from an old server). Ports from an old server's nginx files do not matter, only the domains do. A port you choose yourself is refused if something holds it, with the name of what holds it.

## Moving from an old server

- **Databases.** With `create_database`, the site uses the MySQL database and login the panel makes. `DB_*` values from an old `.env` are left out, so the old server's login cannot lock the site out. Import your data into the new database (phpMyAdmin, or `mysql` on the server); `import-database` can import it from the site's folder (put the dump there first with `upload-file` for small ones, or copy it with `scp` for big ones).
- **APP_KEY.** Keep the old server's `APP_KEY` in the env so data it encrypted still opens. A deploy only creates a key when there is none.
- **Special nginx rules.** Paths the old nginx sent elsewhere (callbacks, webhooks) can be added with `update-nginx`.
- **Allow the tools in Claude Code.** In auto mode Claude Code may ask before each Laravelify call or before reading backup files. Allow them once: run `/permissions` in Claude Code and add `mcp__laravelify`.

## Good to know

- Deploys started by the assistant show **Mcp** as their trigger, in the panel and in Telegram.
- `/mcp` signs in with the token only, so the [access prompt](/security/authentication#access-prompt-for-the-panel-and-phpmyadmin) does not get in the way. Ten wrong tokens in a minute block that IP for a minute.
- Behind the Cloudflare tunnel the address is your panel's normal HTTPS domain; nothing else needs opening.
