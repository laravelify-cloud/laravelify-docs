**Tools → Database** shows every database on the server: MySQL (or MariaDB), PostgreSQL, SQLite (each website's file), and MongoDB, with its engine, size and tables. It uses the panel's own logins, so it sees everything the panel manages.

## Databases and tables

- The lists are spreadsheet grids: click a header to sort, use the funnel on a header to filter by its values (with counts) or a condition, and the **⋮** menu to pin, size, and hide columns. **Search** looks in every column.
- **Export** downloads a dump (MySQL and PostgreSQL as SQL, SQLite as the database file, MongoDB as a `mongodump` archive), and **Back up** sends one database to your backup storage (it shows under **Backups → Databases**).
- Sizes and row counts are each engine's own figures and can be a little behind.

## Import a dump

A MySQL database → **Import SQL** loads a `.sql` or `.sql.gz` dump (from mysqldump, phpMyAdmin, DataGrip, TablePlus, or a Laravelify backup) into that database.

<Steps>
  <Step title="Pick the file">
    Any size up to 20 GB. It goes up in 8 MB pieces, so it passes every upload limit, and a piece lost to a dropped connection is sent again. The dialog shows how much is uploaded.
  </Step>
  <Step title="Empty the database first (optional)">
    Tick it when the dump creates tables the database already has (for example tables the website's migrations made). Every table is deleted before the import.
  </Step>
  <Step title="Watch it run">
    The import runs in the background: a progress bar shows how much of the file is in and the time left, in every open tab, and you can leave the page. One import runs per database at a time.
  </Step>
</Steps>

It is fast: the file is read and unzipped in pieces and streamed into one `mysql` process, with foreign key and unique checks off and one commit at the end, the way DataGrip and mysqldump restores run. A 666 MB dump (59 MB as `.sql.gz`, 98 tables) takes about 30 seconds; 1 GB takes about a minute. When MySQL stops on an error, the task shows its message, with the line of the dump. The uploaded file is deleted afterwards.

<Tip>
AI assistants import too, with the MCP tool `import-database` (a dump already in the website's folder).
</Tip>

## Empty or drop several tables

On a database's **Tables** tab, tick tables (the header box ticks every table shown, after filters and search), then **Empty selected** (deletes their rows) or **Drop selected** (deletes the tables). Both ask first, and run with foreign key checks off, so tables that point at each other go together. Back up the database first if you may need the rows again.

## PostgreSQL, SQLite and MongoDB

- PostgreSQL and SQLite tables open in the same rows grid as MySQL: search, header filters, sorting, adding, changing, and deleting rows (by primary key; a table without one is read-only), and an **SQL** tab.
- MongoDB collections show their documents as JSON, newest first, with a JSON filter like `{"status": "active"}`. Add, change, or delete one document at a time.
- **Changes and undo** is for MySQL only; changes made in the other engines cannot be undone from the panel.

## Rows

Open a table to see its rows a page at a time (25 to 500 per page).

- Click a column name to sort, use **Search every column**, or add **Filters** on single columns: contains, =, ≠, starts with, ends with, regex, >, <, NULL, not NULL.
- Click a row to see every value in full. **Edit** changes it, **Add row** adds one (blank fields get their default or the next number), and **Delete** removes one or many (tick rows first).
- A table without a primary or unique key is read-only here, because a row could not be found again safely.
- **Structure** lists the columns with their types, keys, and defaults.

### Editing a row

Each column gets a field that fits it: date, datetime, and time columns open the browser's date and time picker (with **Now** and **Clear**), enum columns a list of their values, and long text a text box. **NULL** on the right stores no value. Values are saved in MySQL's own format (`2025-02-23 17:59:37`).

### Related rows

When a column points at another table (a foreign key), its header shows `→ table` and its values are links: one click opens that table showing only the row it points at. When other tables point at a column (usually `id`), its header shows `← N`; click a value to pick one of those tables, like `customers (currency_id)`, and see only the rows that point at it. The record dialog has the same links and a **Related rows** list.

### The grid

Rows show in a grid (AG Grid Community) that reads them from the server as you scroll, 100 at a time, sorted and filtered in MySQL, so tables of any size open fast.

- **Funnel** on a header: tick the values to show, from a list of the column's values with how many rows have each (**(Empty)** is NULL), or set a condition (contains, is exactly, starts with, a pattern, empty).
- **⋮** on a header: sort, pin left or right, fit columns to their content, hide a column, choose the columns to show, reset.
- Columns have fixed widths (numbers fit 7 digits, text 220px) and can be resized, moved, and pinned; the layout is kept per table in your browser.
- Hover a cut value to see it whole, click a cell to read or copy it, and double-click a row to open its record. Tick rows to delete them.

## Encrypted columns

Some websites save columns encrypted, like a passport number saved with `encryptString()`. Under **Database → Encryption**, add the website's method:

- **Runs in the website:** a PHP or Laravel website. The code runs in its folder, as its user, with its Laravel app loaded (untick that for plain PHP), so it uses the website's own helpers and keys. The panel never sees them, and the code is stored encrypted.
- **Encrypt:** the body of `function (string $text)` that returns the encrypted text, like `return encryptString($text);`.
- **Decrypt** (optional): the same the other way, like `return decryptString($text);`.

**Try a method** encrypts a text and decrypts it again. Then use it:

- **Search** → **Encrypt first with**: what you type is encrypted, and the search looks for that.
- A table **filter** → **Encrypted with**.
- A record → **Show decrypted with…** shows every value that decrypts.

### Mark a column encrypted

Tell the panel once which columns are encrypted, and it handles them everywhere. On a column header open **⋮ → Encrypted with… ▸** and pick the method, or pick it in the **Encrypted with** column of the table's **Structure** tab. The column then shows a lock in its header, and:

- The grid shows its values decrypted. **⋮ → Show as stored (encrypted)** shows the stored values again.
- The header funnel lists the decrypted values and searches them. **Is exactly** and **Is not** encrypt what you type first.
- The table's search, and the search on the Database page, also look for what you type encrypted with each column's method. You don't pick a method.
- The record shows the value decrypted, with the stored value below it. **Edit** shows it decrypted and saves a changed value encrypted. An unchanged value stays as stored.

Only the setting is saved. The data in the database is not changed, and the panel never stores a decrypted value. Key columns stay as stored in the grid, because rows are found by their stored keys. Sorting an encrypted column sorts by the stored value.

<Note>
  Searching only finds a value when the method gives the same result for the same text every time (a fixed IV, like an IV taken from the key). Laravel's own `encrypt()` gives a new result each time, so its values can be decrypted but not searched.
</Note>

## SQL

Run SQL from the **SQL** tab of the Database page (pick the database), of a database, or of a table (it starts with `SELECT * FROM table LIMIT 100`).

- The editor colors the SQL, numbers the lines, and **autocompletes** keywords, the database's tables, and their columns (also after an alias, like `m.` in `FROM migrations m`). **Ctrl+Space** shows the list, **Tab** or **Enter** takes a suggestion.
- A selection runs on its own, otherwise the whole box; **Ctrl+Enter** runs.
- Up to 1,000 rows come back, in the rows grid: filter any column by values or a condition, sort, search, and page through them. A result can be downloaded as `INSERT` statements.
- SQL typed here is not in the change log, so it cannot be undone.

## SQL history

The **History** tab of a database keeps every query run in it (the last 500), newest first and grouped by day: what came back, how long it took, and who ran it. Filter by **Read**, **Changed**, or **Failed**, or search the SQL.

- For an `UPDATE` or `DELETE` of one table, the rows it matched are saved before it runs (up to 200), and for an `UPDATE` also after: **Changed rows** shows each changed cell as old → new.
- **Run** puts the query back in the editor and runs it (it asks first when it changed rows); **Edit** only puts it there.

## Triggers, events, procedures, functions

The **Triggers, events, routines** tab lists them. View the definition, **Change** it (if MySQL refuses the new one, the old one is put back), create a **New** one from a `CREATE` statement, or drop it.

## Search everywhere

Find a value in every table of every database, or in the databases you choose, like a passport number. Match it as **contains**, **is exactly**, **starts with**, or **regex** (MySQL's syntax, like `^AZE[0-9]{7}$`), optionally only in columns named like `firstname`. Each result shows the table, the row's key, and the matching values; **Open record** opens it. You can also search **table names** and **column names**.

## Changes and undo

Every row added, edited, or deleted here, and every trigger, event, procedure, or function created, changed, or dropped, is logged with what was there before, under **Changes**.

- **Undo** puts back only that row or object. Rows other people added or changed meanwhile stay as they are.
- When the row was changed again since your change, Undo stops and shows what changed; **Undo anyway** writes the old values over them.
- An undo is a change of its own, so it can be undone too.
- Before deleting rows you can **save a copy of the table** (put back whole from the log with **Restore table copy**) and start a **backup of the whole database**.

<Warning>
  Changes made outside this tool (by your apps, phpMyAdmin, or migrations) are not in the log and cannot be undone here. For those, restore from a backup.
</Warning>
